Session-first. Sample-accurate. Text on disk.

A native Linux DAW, written from scratch in C++20 — no framework, no toolkit, no runtime.

Source on GitHub Build it

Your set is text.

A project is one line-oriented plain-text file with a byte-identical round-trip and stable per-entity uids. A melody is eight note lines. Diff a mix, branch an arrangement, review a track in a pull request, generate a set from a script.

The audio thread shares nothing.

No allocation, no locks, no pointers into GUI memory: the interface reaches the engine through a lock-free command ring and a block of atomics. Launches are split inside the buffer, so a clip starts on the exact frame of its quantum rather than at the top of the next block.

CI plays what it builds.

Every push builds the whole application, runs 500+ headless assertions, then renders five passes of the demo set to FLAC and prints the peak and RMS of each into the run summary. The pipeline does not just compile this DAW. It hands you the audio.

What it does

Session View

Clip grid, scenes, per-track stop, scene launch, mixer strip with pan, fader, peak meters, mute / solo / arm.

Piano roll

Fold, 1/16 grid, drag / resize / delete, multi-note selection, velocity lane, live playhead.

Warping

Beats is a two-grain overlap-add stretcher that preserves pitch; Repitch transposes with the tempo.

Recording

Arm a track, click an empty slot. Quantised start and stop; takes return warped to the session tempo.

MIDI in

ALSA sequencer port plus an FL-Studio-style computer keyboard, routed per block to armed tracks. Overdub included.

Plugins

LV2 and CLAP in the signal path with note input, a filterable browser, bypass and parameter knobs.

Buses

Post-fader sends into four return chains and a master chain, with plugin delay compensation across every parallel path.

Generative clips

Launch probability and follow actions, scheduled through the same quantised path — deterministic offline.

Engine daemon

latticed hosts the transport and the sample pool in its own process over shared-memory rings.

Windows

The headless engine cross-builds with mingw-w64 and its suite runs under Wine on every push.

Verified, not asserted

Quickstart

make                    # build
make test               # headless suite: engine, IPC, daemon, render, plugin scan
make tools              # gen_demo, render, pitch_check, plugin_scan

build/gen_demo ~/Music/Demo    # write a four-scene demo set

The product is NxTakt; the source tree still spells the old name, so the binary is build/lattice and sets are .lattice until that rename lands.
